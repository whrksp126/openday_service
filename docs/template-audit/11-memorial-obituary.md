# 11. 부고 · 추모 안내

| 항목 | 값 |
|---|---|
| id | `memorial-obituary-template-001` |
| 카테고리 | 부고/추모 · 부고 |
| 콘셉 | 세이지 · 차콜 절제 톤. 국화 커버 |
| 테마 | 오프화이트 배경 + 다크 세이지 accent · `showEnglishTitle: false` |
| 페이지 높이 | 3222px (4구간) |
| 캡처 | `_shots/memorial-obituary-template-001__00~03.png` |

**모듈 구성 (8개)**
`main → greeting(부고) → datetime → venue → contact(상주) → tab(안내) → account(마음 전하실 곳) → guestbook(추모의 글)`

---

## 이 템플릿의 핵심 진단

> **11개 중 가장 시급하다.** 톤과 국화 커버는 잘 잡혀 있지만, 부고로서 반드시 있어야 할 정보가 없고, 웨딩 잔재 문구가 가장 부적절한 자리에 남아 있다.
>
> 부고는 실수가 곧 결례가 되는 유일한 카테고리다. 다른 템플릿의 오류는 "덜 만들었네"지만, 여기서는 **"고인과 유가족에 대한 무례"** 로 읽힌다.

## P0 — 치명

### M-1. 고인의 성함과 별세 일시가 없다

**현상.** 화면 전체에서 고인에 대한 정보는 다음이 전부다.

- 커버: `삼가 고인의 명복을 빕니다` / `발인 2026. 08. 05. (수) AM 7:00` / `한빛장례식장 3층 특7호실`
- 인사말: `삼가 고인의 별세를 알려드립니다` — "평소 고인께서 베풀어 주신 따뜻한 정에…"

**고인의 성함이 어디에도 없다.** 별세일시도, 향년도 없다.

**왜 치명적인가.** 부고의 존재 이유는 **"누가 돌아가셨는지 알리는 것"** 이다. 그 정보가 없으면 부고가 아니다. 받는 사람은 상주 이름(`홍길동`)을 보고 유추해야 한다.

**수정안 — 부고의 표준 형식을 갖춘다.**

```
        訃  告

  홍○○ 님께서 2026년 8월 3일(일)
  향년 82세로 별세하셨기에
  삼가 알려 드립니다.

  빈소   한빛장례식장 3층 특7호실
  입관   2026. 8. 4. (월) PM 2:00
  발인   2026. 8. 5. (수) AM 7:00
  장지   하늘추모공원 (경기도 파주시)

  상주   장남 홍길동 · 차남 홍길서
  자부   김○○ · 이○○
```

seed 반영:

```ts
textSlots: {
  topText: '삼가 고인의 명복을 빕니다',
  brandTitle: '故 홍○○',                                  // 고인 성함 — 신설
  subText: '2026. 08. 03. (일) 별세 · 향년 82세',           // 별세일시/향년 — 신설
  bottomText: '발인 2026. 08. 05. (수) AM 7:00',
  extraText: '한빛장례식장 3층 특7호실',
}
```

`datetime` 모듈도 **발인 하나만** 표시하고 있다. 빈소 개시 · 입관 · 발인 · 장지 도착을 **`timeline` 모듈**로 시간순 표시하는 것이 실제 조문객에게 가장 유용하다.

### M-2. "카카오톡으로 공유하기" 노란 버튼 + "청첩장 주소 복사하기"

**현상.** 부고 하단에

- **형광 노랑(#FAE100)** 카카오 공유 버튼
- **`청첩장 주소 복사하기`**

**왜 치명적인가.**

1. **`청첩장`** — 부고에 결혼 용어다. 유가족이 이 초대장을 보냈다면 사과해야 할 수준의 오류다.
2. **형광 노랑** — 세이지·차콜의 절제된 화면에서 유일하게 튀는 색이고, 조문 맥락에서 경박하게 읽힌다.
3. **`공유하기`** — 부고는 "공유"보다 **"알리다"** 가 맞는 동사다.

**수정안.** → [00-common.md C-2](00-common.md)

```ts
// memorial 카테고리 오버라이드
kakaoLabel: '카카오톡으로 알리기',
copyLabel:  '부고 주소 복사하기',
kakaoStyle: 'outline',      // 노란 풀블리드 금지, 아웃라인 + 테마 accent
```

### M-3. 섹션 라벨이 "행사 일시" / "행사 장소"

**현상.** 발인 정보 섹션 제목이 **`행사 일시`**, 빈소 정보 섹션 제목이 **`행사 장소`**.

**왜 치명적인가.** 장례를 "행사"라고 부른다. 유가족이 보면 즉시 눈에 띄는 결례다.

**수정안.** → [00-common.md C-6](00-common.md)

| 현재 | 필수 변경 |
|---|---|
| `행사 일시` | **`발인 일시`** (또는 `장례 일정`) |
| `행사 장소` | **`빈소`** |
| `안내` | 유지 |
| `상주` | 유지 |
| `마음 전하실 곳` | 유지 |
| `추모의 글` | 유지 — 좋다 |

영문 라벨은 이 템플릿에서 이미 꺼져 있다(`showEnglishTitle: false`). 올바른 판단이다.

### M-4. 커버에 장식용 `✦` 스파클

**현상.** 국화 사진 우하단에 **회색 반짝임 장식**이 떠 있다.

**왜 치명적인가.** 부고에 장식 반짝임이다. 다른 템플릿(졸업식·전시회)에서는 "불필요한 노이즈" 수준이지만 여기서는 **명백한 결례**다.

**수정안.** `main` variant 의 장식 요소를 카테고리별로 제어. memorial 은 **모든 장식 강제 OFF**.

## P1 — 주요

### M-5. 상주 연락처가 죽은 회색 버튼

**현상.** `장남 홍길동` / `차남 홍길서` 카드의 통화·문자 아이콘이 **회색 비활성**.

**왜 문제인가.** 부고에서 연락처는 **조문 가능 시간 확인 · 조화 발송 · 위치 문의**에 실제로 쓰인다. 눌리지 않으면 초대장이 기능을 못 한다. → [00-common.md C-10](00-common.md)

### M-6. 제목 중복 — `상주` / `상주`, `마음 전하실 곳` / `마음 전하실 곳`

**현상.**

```
상주
  상주  CHIEF MOURNER
    장남 홍길동
    차남 홍길서

마음 전하실 곳
마음 전하실 곳
  조의금 ▼
```

**수정안.** → [00-common.md C-8](00-common.md)

```ts
// contact
{ koreanTitle: '상주',
  groups: [{ label: '유가족', englishLabel: '', contacts: [...] }] }

// account
{ koreanTitle: '마음 전하실 곳', titleBigVisible: false }
```

`CHIEF MOURNER` 영문 표기도 이 맥락에서는 불필요하다 — 제거.

### M-7. 유가족 구성이 불완전하다

**현상.** 상주 2명(장남·차남)만 있다.

**왜 문제인가.** 부고에는 관습적으로 **배우자 · 자녀 · 사위/며느리 · 손자녀**까지 명시한다. 조문객이 "누구와의 관계로 가는지"를 판단하는 기준이다.

**수정안.**

```ts
groups: [
  { label: '미망인', contacts: [{ name: '김○○', phone: '' }] },
  { label: '아들',   contacts: [{ name: '홍길동', phone: '010-0000-0000' },
                                { name: '홍길서', phone: '010-0000-0000' }] },
  { label: '며느리', contacts: [{ name: '이○○' }, { name: '박○○' }] },
  { label: '딸',     contacts: [{ name: '홍길순' }] },
  { label: '사위',   contacts: [{ name: '최○○' }] },
]
```

전화번호는 **상주(연락 담당)에게만** 붙이는 것이 관습이다. 나머지는 이름만 — 이 경우 M-5 의 "번호 없으면 아이콘 미렌더" 처리가 특히 잘 맞는다.

### M-8. 조문 정보가 얇다

**현상.** `안내` 탭 3개.

| 탭 | 현재 내용 |
|---|---|
| 조문 안내 | `조문은 24시간 가능합니다.` |
| 장지 | `하늘추모공원 (경기도 파주시)` |
| 오시는 길 | `2호선 신촌역 2번 출구 · 장례식장 지하주차장 이용` |

**없어서 곤란한 것.**

| 항목 | 왜 필요한가 |
|---|---|
| **조화 · 근조기** | 보낼지 말지, 어디로 보낼지. 가장 많이 묻는 것 |
| **식사 제공 여부** | 조문 시간대 결정 |
| **주차** | 현재 한 줄뿐. 무료 여부·주차권 |
| **장지 발인 동행** | 동행 가능한지, 버스가 있는지 |
| **종교 의식** | 기독교/불교/천주교 — 조문 예법이 달라진다 |
| **부의금 사절 여부** | 사절이면 반드시 명시해야 한다 |

**수정안 — 탭 재구성**

```
조문 안내 : 조문은 24시간 가능합니다. 식사가 준비되어 있습니다.
조화 안내 : 조화·근조기는 장례식장으로 보내주시기 바랍니다. (또는 정중히 사양합니다)
장례 일정 : 입관 8/4(월) PM 2:00 · 발인 8/5(수) AM 7:00
장지     : 하늘추모공원 (경기도 파주시) · 발인 동행 버스 1대 운행
주차     : 장례식장 지하 1~3층 · 조문객 3시간 무료
오시는 길 : 2호선 신촌역 2번 출구 도보 8분 · 셔틀 없음
```

### M-9. `발인 2026. 08. 05.` 만으로는 조문 시점을 알 수 없다

**현상.** 커버와 datetime 모두 **발인 시각**만 표시.

**왜 문제인가.** 조문객이 알아야 하는 것은 발인이 아니라 **"언제 가면 되는가"** — 빈소 개시 시각이다. 발인 당일 새벽 7시에 가라는 뜻으로 오해할 여지가 있다.

**수정안.** M-1 의 `timeline` 모듈로 전체 일정을 시간순 제공.

### M-10. 상세주소 미노출

`한빛장례식장 3층 특7호실` 만 표시되고 `서울특별시 서대문구 연세로 50` 이 안 보인다.
장례식장은 **택시로 이동하는 비율이 높아** 주소 텍스트가 특히 중요하다. → [00-common.md C-9](00-common.md)

## P2 — 개선

### M-11. 캘린더 주말 빨강/파랑

**현상.** 8월 달력에서 일요일이 **빨강**, 토요일이 파랑.

**왜 문제인가.** 부고 화면에서 빨간 숫자는 부적절하다. 절제된 세이지·차콜 팔레트를 깨는 유일한 요소이기도 하다.

**수정안.** memorial 은 `weekendColors: null` — 전 요일 동일 차콜, 발인일만 다크 세이지 하이라이트. → [00-common.md C-13](00-common.md)

### M-12. 캘린더 모듈 자체가 필요한가

부고에서 월 전체 달력을 보여주는 것은 정보 가치가 낮다. 발인일 하나를 위해 화면 절반을 쓴다.

**수정안.** memorial 에서는 `datetime` 모듈의 캘린더를 끄고(`showCalendar: false`), 대신 **장례 일정 timeline** 을 넣는다.

### M-13. 방명록 샘플 문구

`이 방명록은 미리보기용 예시입니다. 에디터에서는…` 이 **추모의 글** 자리에 나온다. → [00-common.md C-3](00-common.md)

memorial 샘플: `삼가 고인의 명복을 빕니다. 유가족께 깊은 위로의 말씀을 전합니다.`

### M-14. 인사말 본문은 잘 쓰였다

> "평소 고인께서 베풀어 주신 따뜻한 정에 깊이 감사드립니다. 갑작스러운 비보를 전하게 되어 송구한 마음뿐입니다. 부디 오시어 고인의 마지막 길을 함께해 주시면 감사하겠습니다."
> — `상주 일동`

톤·격식·서명 모두 적절하다. **유일하게 서명이 제대로 된 템플릿**이다. 유지.

## 이미지 애셋 교체 계획

### 현재 상태

| 용도 | 개수 | 상태 |
|---|---|---|
| 커버 | 1 (아치형 국화) | **품질·톤 양호. 장식 `✦` 만 제거하면 유지 가능** |
| gallery | 0 | **없는 것이 맞다** — 부고에 갤러리는 부적절 |

이 템플릿은 **이미지 작업이 가장 적다.** 커버 국화 사진이 카테고리에 정확히 맞고 아치형 마스크도 적절하다.

### 선택 — 커버 대안 1~2종

사용자가 고를 수 있게 대안을 준비하는 정도면 충분하다.

```
Single white chrysanthemum flower resting on dark folded linen on a weathered
dark wood surface, deep muted sage green and charcoal tones, soft directional
low light from one side, deep shadows, quiet and solemn mood, no decorative
elements, no sparkles, shallow depth of field, fine art still life photography,
vertical 3:4 composition
```

```
Soft-focus close-up of white chrysanthemum petals filling the frame, very
low saturation, cool grey and pale ivory tones, gentle diffused light, calm
and restrained, no decorative elements, fine art photography, vertical 3:4
composition
```

> 부고 이미지 생성 시 프롬프트에 반드시 `no decorative elements, no sparkles, no bright colors, solemn, restrained` 를 명시한다. 기본 생성 모델은 꽃 사진에 밝고 화사한 톤을 얹는 경향이 있다.
